## Medusa 할인 구조

할인은 **Promotion 모듈**이 담당한다. 핵심 흐름은 다음과 같다.

1. 고객이 코드를 입력(`POST /store/carts/:id/promotions`)하거나 자동 프로모션이 감지된다.
2. `promotionService.computeActions(cart, codes)` 호출 → `ComputeAction[]` 반환.
3. 반환된 액션을 `LineItemAdjustment` / `ShippingMethodAdjustment` 레코드로 변환해 Cart에 저장.

참고: [사용자 여정 분析 05-프로모션-적용](../사용자 여정 분析/05-프로모션-적용/README.md)

## 쿠폰 (Promotion)

### 적용 범위별 설정

| 요구사항 | ApplicationMethod 설정 | 동작 |
|----------|----------------------|------|
| 상품 단위 할인 | `target_type=items`, `allocation=each` | 조건 충족하는 각 LineItem에 Adjustment 생성 |
| 상품 그룹 단위 할인 | `target_type=items`, `allocation=across` | 조건 충족 아이템들에 총 할인액을 금액 비율로 분산 |
| 주문 전체 단위 할인 | `target_type=order` | 전체 주문 합계에서 고정 금액 또는 비율 차감 |
| 배송비 할인 | `target_type=shipping_methods` | ShippingMethodAdjustment 생성 |

### 할인 타입

| `ApplicationMethod.type` | 의미 |
|--------------------------|------|
| `percentage` | 대상 금액의 n% 차감 |
| `fixed` | 고정 금액 차감 |
| `fixed_rate` | 아이템별 고정 단가 차감 |

### 코드 방식 vs 자동 적용

| `Promotion.is_automatic` | 동작 |
|--------------------------|------|
| `false` | 고객이 코드를 직접 입력해야 적용 (쿠폰 코드) |
| `true` | 장바구니 갱신 시 `computeActions` 내에서 자동 포함 |

### 사용 한도 관리

`Campaign` → `CampaignBudget`으로 사용 횟수(`type=usage`) 또는 사용 금액(`type=spend`) 한도를 관리한다. 주문 완료 시 `registerUsageStep`이 실행되어 차감된다.

## 포인트

**현황 (사실)**: Medusa에 별도 포인트 모듈이 없다.

**유사 구조 (사실)**: `CartCreditLine` / `OrderCreditLine`이 존재한다.

```
CartCreditLine: reference, reference_id, amount
OrderCreditLine: version, reference, reference_id, amount
```

이 구조는 외부 시스템(포인트, 적립금, 기프트카드 등)에서 차감할 금액을 기록하는 용도로 쓸 수 있다.

**구현 방향 (추정)**: 포인트 잔액 관리는 외부 모듈 또는 별도 서비스에서 담당하고, 사용 금액을 `CreditLine`으로 Cart/Order에 연결하는 방식이 현재 구조와 가장 자연스럽게 맞다. 단, CreditLine이 금액 재계산 흐름(`refreshCartItemsWorkflow`)에 자동으로 포함되는지는 별도 확인이 필요하다.

**`is_giftcard` 아이템**: CartLineItem에 `is_giftcard` 필드가 있어, 기프트카드 상품은 세금 계산에서 제외된다(`getItemTaxLinesStep`에서 필터링). 포인트와는 다른 개념이다.

## BUYGET 프로모션

`Promotion.type = BUYGET`: 조건 충족 시 특정 상품을 무료 증정하는 구조. `computeActions` 내부의 `getComputedActionsForBuyGet()`으로 처리된다. 주문 요구사항에는 언급되지 않았으나 확장 시 활용 가능하다.
