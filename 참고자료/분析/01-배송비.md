## Medusa 배송 구조

```
FulfillmentSet (판매 채널에 연결)
  └── ServiceZone (서비스 가능 지역 묶음)
        ├── GeoZone (country / region / city / postal_code 조건)
        └── ShippingOption (배송 옵션, price_type: flat | calculated)
              ├── ShippingOptionRule (적용 조건: attribute / operator / value)
              └── ShippingProfile (상품 배송 유형 분류)
```

배송 옵션 조회 시 `shipping_address` 좌표가 GeoZone 조건과 매칭되어 적용 가능한 옵션만 반환된다.

참고: [사용자 여정 분析 04-배송옵션-선택](../사용자 여정 분析/04-배송옵션-선택/README.md)

## 배송 그룹 단위 묶음

**현황 (사실)**: Medusa는 Cart당 ShippingMethod를 1개만 허용한다. 새 배송 방법을 추가하면 기존 방법이 소프트 삭제된다 (`addShippingMethodToCartWorkflow` Step 9a/9b).

**의미**: "상품을 여러 배송 그룹으로 나눠 그룹별 배송비 부과"는 현재 구조로는 불가능하다.

ShippingProfile로 상품을 논리적으로 분류할 수 있으나, 이는 배송 옵션 필터링 용도이고 그룹별 배송비를 별도로 계산하지 않는다.

**확장 방향 (추정)**: 복수 ShippingMethod 동시 허용 + 그룹별 배송비 합산 구조를 별도로 설계해야 한다.

## 조건부 무료배송

Medusa에서 구현 경로가 두 가지다.

### 방법 A — ShippingOptionRule

`ShippingOptionRule`은 `attribute`, `operator`, `value` 세 필드로 배송 옵션 노출 조건을 정의한다.

```
attribute: "cart_subtotal"
operator:  "gte"
value:     50000
```

이 규칙이 붙은 ShippingOption은 장바구니 소계가 50,000원 이상일 때만 목록에 노출된다. 가격을 0으로 설정하면 무료배송 옵션으로 동작한다.

**한계**: 조건 이탈(반품으로 소계 감소) 시 자동으로 유료 전환되지 않는다. 주문 완료 후 ShippingOption은 Order에 스냅샷으로 복사(`OrderShippingMethod`)되어 이후 변경되지 않는다.

### 방법 B — Promotion(배송비 할인)

`ApplicationMethod.target_type = shipping_methods`로 배송비를 0으로 만드는 프로모션을 생성한다. 규칙(`PromotionRule`)으로 최소 주문금액 조건을 부여한다.

이 방법은 `refreshCartItemsWorkflow` 내에서 프로모션이 재계산되므로, 체크아웃 완료 전까지는 장바구니 변경 시 배송비 할인이 자동으로 재평가된다.

**한계**: 주문 완료 후 반품 시에도 배송비 재계산은 자동으로 일어나지 않는다. ([04-부분취소-환불.md](./04-부분취소-환불.md) 참고)

## 도서산간 별도 배송비

GeoZone은 `country`, `region`, `city`, `postal_code` 네 가지 정밀도를 지원한다.

구현 방법:
1. 도서산간 우편번호(또는 시·군) 범위를 별도 ServiceZone으로 생성
2. 해당 ServiceZone에 도서산간 추가요금이 반영된 ShippingOption을 연결
3. 배송 옵션 조회 시 `shipping_address.postal_code`가 GeoZone 조건과 매칭되면 해당 옵션만 노출

**확인된 사실**: GeoZone 타입 `postal_code`가 존재하며, `schema.fulfillment.prisma`에서 확인됨.
