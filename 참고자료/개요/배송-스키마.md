# 배송(Fulfillment) 모듈 스키마

Fulfillment 모듈의 DB 엔티티 구조. 배송 그룹, 지역별 배송비, 조건부 무료배송 구조 중심으로 정리.

상위: [README.md](README.md)

---

## 엔티티 관계도 (배송 설정)

```
FulfillmentSet (배송 세트)
 └── ServiceZone[] (지역 구분 단위)
      ├── GeoZone[] (실제 지역 범위 정의)
      └── ShippingOption[] (이 존에서 사용 가능한 배송 옵션)
           ├── ShippingOptionType (배송 유형)
           ├── ShippingOptionRule[] (조건부 노출 규칙)
           ├── ShippingProfile (배송 프로파일)
           └── FulfillmentProvider (배송 업체)
```

cascade delete 체인: `FulfillmentSet 삭제 → ServiceZone 삭제 → GeoZone + ShippingOption 삭제`

### GeoZone (지역 범위 정의)
[`packages/modules/fulfillment/src/models/geo-zone.ts`](../../packages/modules/fulfillment/src/models/geo-zone.ts)

ServiceZone의 실제 지리적 범위를 정의.

| 필드 | 타입 | 비고 |
|------|------|------|
| `type` | enum | `country` / `province` / `city` / `zip` |
| `country_code` | text | 필수 |
| `province_code` | text, nullable | `province`/`city`/`zip` 타입에서 사용 |
| `city` | text, nullable | `city` 타입에서 사용 |
| `postal_expression` | json, nullable | `zip` 타입에서 우편번호 범위/패턴 |

**도서산간 배송비 구현 구조** (사실):

| type | 사용 필드 조합 | 예시 |
|------|--------------|------|
| `country` | `country_code` | 한국 전국 |
| `province` | `country_code` + `province_code` | 제주도 (`jeju`) |
| `city` | `country_code` + `province_code` + `city` | 특정 시/군/구 |
| `zip` | `country_code` + `postal_expression` | 우편번호 범위/패턴 |

제주/도서산간 적용 방법:
1. "제주 ServiceZone" 생성
2. `type: "province"`, `province_code: "jeju"` GeoZone 연결
3. 해당 ServiceZone에 도서산간 요금의 ShippingOption 연결

### ShippingOptionRule (조건부 배송 노출 규칙)
[`packages/modules/fulfillment/src/models/shipping-option-rule.ts`](../../packages/modules/fulfillment/src/models/shipping-option-rule.ts)

ShippingOption이 Cart에 노출되는 조건을 정의. 조건 불충족 시 해당 배송 옵션이 선택 불가.

| 필드 | 타입 | 비고 |
|------|------|------|
| `attribute` | text | 평가 대상 속성 (예: `cart.subtotal`) |
| `operator` | enum | `in` / `eq` / `ne` / `gt` / `gte` / `lt` / `lte` / `nin` |
| `value` | json, nullable | 비교 값 (숫자·문자열·배열 모두 수용) |

operator enum 정의: [`packages/core/utils/src/common/rules.ts`](../../packages/core/utils/src/common/rules.ts)

**조건부 무료배송 구현 예시**:

5만원 이상 무료배송:
```
attribute = "cart.subtotal"
operator  = "gte"
value     = 50000
```

특정 배송 유형(예: 냉장 배송)에만 적용 가능한 옵션:
```
attribute = "shipping_option.type_id"
operator  = "eq"
value     = "sotype_cold_chain"
```

한 ShippingOption에 여러 룰 연결 가능 (`rules: hasMany`). 복수 룰의 AND/OR 평가 방식은 서비스 레이어에서 결정 (모델에 명시 없음).

## 배송 상품군 분리 구조 요약

요구사항의 "상품군 단위 배송비 그룹이 있고 거기에 상품이 묶여야 함" 항목 관련:

Medusa의 접근: `ShippingProfile`을 상품에 연결해 배송 그룹을 구분.

```
Product → ShippingProfile → ShippingOption (ShippingProfile과 연결된 것만 선택 가능)
```

- ShippingProfile `type: "default"` → 일반 상품 배송 옵션
- ShippingProfile `type: "cold_chain"` (커스텀) → 냉장 배송 전용 옵션
- 여러 ShippingProfile을 가진 상품이 같은 장바구니에 있으면 → 각 Profile별로 ShippingMethod를 별도 선택

배송비 그룹 분리가 Cart 레벨에서 자동으로 강제되는 구조는 아님. 프론트엔드 / 비즈니스 로직에서 `ShippingProfile` 기준으로 배송 옵션을 분리해 제시하는 방식.
