# 정산/과세 구조 — 요구사항과 Medusa 구현 대응 분석

요구사항:
- "정산/과세 대상에 포함되는 금액과 포함되지 않는 금액 존재"
- "할인액수를 어떻게 상품 간에 분담할지에 따라 과세 신고액이 바뀐다"
- "포인트 사용"

상위: [README.md](../개요/README.md)

---

## 요약

Medusa는 정산/과세 관련 금액을 3개 레이어로 관리한다.

1. **세금 계산**: `TaxLine`(세율) → `decorateCartTotals()`(런타임 계산) → `OrderSummary.totals.tax_total`
2. **과세 제외**: `CreditLine`(포인트 등)은 `accounting_total`에서 제외
3. **할인 분담**: `ApplicationMethod.allocation`으로 아이템별 과세 기준 금액이 달라짐

---

## 1. 세금 계산 구조

### 세율 저장 위치

**장바구니**: [`packages/modules/cart/src/models/line-item-tax-line.ts`](../../packages/modules/cart/src/models/line-item-tax-line.ts) (테이블: `cart_line_item_tax_line`)

**주문 확정 후**: [`packages/modules/order/src/models/line-item-tax-line.ts`](../../packages/modules/order/src/models/line-item-tax-line.ts) (테이블: `order_line_item_tax_line`)

공통 구조:
```
code         세율 코드 (예: "KR_VAT")
rate         세율 (예: 10.0)
tax_rate_id  Tax 모듈의 TaxRate 참조
provider_id  세율 계산 프로바이더
```

배송비 세율도 별도로 저장: `cart_shipping_method_tax_line`, `order_shipping_method_tax_line`

### 세금 계산 로직

파일: [`packages/core/utils/src/totals/line-item/index.ts`](../../packages/core/utils/src/totals/line-item/index.ts)

```typescript
// is_tax_inclusive = false인 경우
tax_total = (subtotal - discount_subtotal) * taxRate

// is_tax_inclusive = true인 경우
subtotal = unit_price * quantity / (1 + taxRate)  // 세금 역산
tax_total = unit_price * quantity - subtotal
```

`is_tax_inclusive` 필드가 아이템별로 설정되므로 세금 포함가/제외가 상품마다 다를 수 있다.

### 세금 합계가 저장되는 곳

`OrderSummary.totals` JSON에 포함 (DB 컬럼으로 직접 저장 안 함):

```
item_tax_total             아이템 세금 합계
shipping_tax_total         배송비 세금 합계
tax_total                  전체 세금 합계 (item + shipping)
original_tax_total         할인 전 세금 합계
discount_tax_total         할인으로 줄어든 세금
```

## 2. 과세 제외 금액 — `CreditLine` (포인트/크레딧)

### 장바구니 단계

파일: [`packages/modules/cart/src/models/credit-line.ts`](../../packages/modules/cart/src/models/credit-line.ts)

```
CreditLine
  amount        포인트 사용액
  reference     출처 유형 (예: "points", "gift_card")
  reference_id  출처 ID
```

### 합계 계산에서의 처리

파일: [`packages/core/utils/src/totals/cart/index.ts`](../../packages/core/utils/src/totals/cart/index.ts)

```typescript
// 크레딧 라인 합계 계산 (현재 taxRate = 0 하드코딩)
const creditLinesTotal = calculateCreditLinesTotal(cartLike.credit_lines, 0)

// total에서 직접 차감
const total = MathBN.sub(
  MathBN.add(subtotal, taxTotal),
  discountSubtotal,
  creditLinesTotal   // ← 포인트 사용액 차감
)
```

### `accounting_total` — 정산 대상 금액

파일: [`packages/modules/order/src/utils/calculate-order-change.ts`](../../packages/modules/order/src/utils/calculate-order-change.ts)

```typescript
// 초기화 시점
accounting_total = order.total - credit_line_total
```

포인트(CreditLine)로 결제한 금액은 `accounting_total`에서 제외된다. 이것이 "정산/과세에 포함되지 않는 금액"에 해당한다.

**주의**: `processActions()` 이후 `accounting_total = current_order_total`로 덮어써진다. 초기화 시점의 `credit_line_total` 공제 로직은 이후 프로세스에서 유지되지 않는다. `previewOrderChange` 결과의 `accounting_total`이 정확한 과세 대상 금액인지는 현재 데이터로 완전히 확인되지 않는다.

## 3. 할인 분담 방식별 과세 기준 금액 차이

아이템별 `subtotal`과 `discount_subtotal`이 결정되면 세금이 계산된다.

### `allocation = "each"` 예시

```
아이템 A: unit_price=20,000, quantity=2
아이템 B: unit_price=15,000, quantity=1

쿠폰: fixed 5,000원, allocation=each

아이템 A 할인: 5,000원  → 과세 기준 = (40,000 - 5,000) = 35,000원
아이템 B 할인: 5,000원  → 과세 기준 = (15,000 - 5,000) = 10,000원
전체 과세 기준: 45,000원
세금 (10%): 4,500원
```

### `allocation = "across"` 예시

```
아이템 A: subtotal=40,000 (비율 72.7%)
아이템 B: subtotal=15,000 (비율 27.3%)
전체: 55,000원

쿠폰: fixed 5,000원, allocation=across

아이템 A 할인: 5,000 × 72.7% = 3,636원  → 과세 기준 = 36,364원
아이템 B 할인: 5,000 × 27.3% = 1,364원  → 과세 기준 = 13,636원
전체 과세 기준: 50,000원 (동일)
세금 (10%): 5,000원 (동일)
```

`across`는 전체 세금 합계는 `each`와 같지만, **아이템별 과세 기준 금액이 다르다**. 개별 상품 단위로 매출 신고를 할 때 차이가 발생한다.

## 4. 세금 포함/제외 레이블

### `is_tax_inclusive` 필드

| 위치                        | 필드                 | 의미                 |
| ------------------------- | ------------------ | ------------------ |
| `OrderLineItem`           | `is_tax_inclusive` | 이 상품의 단가가 세금 포함가인지 |
| `OrderShippingMethod`     | `is_tax_inclusive` | 이 배송비가 세금 포함가인지    |
| `OrderLineItemAdjustment` | `is_tax_inclusive` | 이 할인이 세금 포함 기준인지   |

`is_tax_inclusive = true`이면 `decorateCartTotals()`에서 세금을 역산(divide)해 `subtotal`을 구한다.

### 세율 0 상품

`OrderLineItemTaxLine`이 없거나 `rate = 0`이면 세금이 붙지 않는다. 식품, 의약품 등 과세 제외 상품에 활용.

## 5. 정산 관련 필드 요약

`OrderSummary.totals` JSON에서 정산/과세와 직접 관련된 필드:

| 필드 | 의미 | 정산 활용 |
|------|------|----------|
| `accounting_total` | `current_order_total - credit_line_total` | 정산 대상 총액 |
| `paid_total` | 결제된 실제 금액 합계 | 입금 확인 |
| `refunded_total` | 환불된 금액 합계 | 환불 처리 확인 |
| `item_tax_total` | 아이템 세금 합계 | 부가세 신고 |
| `shipping_tax_total` | 배송비 세금 합계 | 부가세 신고 |
| `discount_total` | 할인 총액 | 할인 규모 추적 |
| `credit_line_total` | 크레딧(포인트) 사용 총액 | 과세 제외 금액 |

파일: [`packages/core/utils/src/totals/cart/index.ts`](../../packages/core/utils/src/totals/cart/index.ts) (계산 함수)
파일: [`packages/modules/order/src/utils/calculate-order-change.ts`](../../packages/modules/order/src/utils/calculate-order-change.ts) (OrderSummary 조립)

## 6. 요구사항과의 Gap

| 요구사항 항목 | Medusa 지원 여부 | 비고 |
|-------------|----------------|------|
| 과세 제외 금액 분리 (포인트) | ✅ `CreditLine` → `accounting_total` 제외 | |
| 아이템별 세율 | ✅ `OrderLineItemTaxLine` | |
| 배송비 세율 | ✅ `OrderShippingMethodTaxLine` | |
| 할인 분담 방식별 과세 기준 | ✅ `allocation=each/across` | |
| 세금 포함/제외 상품 혼재 | ✅ `is_tax_inclusive` 아이템별 설정 | |
| 정산 대상 금액 명시 | 부분적 — `accounting_total` 존재하나 `processActions()` 후 덮어써짐 | 정확한 과세 기준 금액을 별도 산출하려면 커스텀 로직 필요 |
| 아이템별 매출 신고 금액 | ✅ `OrderLineItem.unit_price` + `OrderLineItemAdjustment.amount` (아이템별 분담 기록됨) | |
