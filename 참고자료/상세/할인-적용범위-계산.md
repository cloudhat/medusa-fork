# 할인 적용 범위 및 계산 — 요구사항과 Medusa 구현 대응 분석

요구사항:
- "쿠폰도 상품별, 상품 그룹별, 전체 주문 단위 등 다양한 적용범위 존재"
- "할인액수를 어떻게 상품 간에 분담할지에 따라 과세 신고액이 바뀐다"
- "증가/차감 요소는 서로 영향을 미친다"

상위: [README.md](../개요/README.md)

---

## 요약

Medusa의 할인은 `Promotion → ApplicationMethod → PromotionRule` 3단 구조로 표현된다. 적용 범위는 `ApplicationMethod.target_type`으로, 아이템 간 분담 방식은 `ApplicationMethod.allocation`으로 결정된다. 실제 평가는 `computeActions()` → `areRulesValidForContext()` 경로에서 **AND 조건**으로 처리된다.

---

## 1. 적용 범위 구조

### `target_type` 3가지

파일: [`packages/modules/promotion/src/models/application-method.ts`](../../packages/modules/promotion/src/models/application-method.ts)

```
ApplicationMethod.target_type
  ├── "order"             → 주문 전체 금액에 할인 적용
  ├── "items"             → 특정 라인 아이템에만 적용 (target_rules로 대상 지정)
  └── "shipping_methods"  → 배송비에만 적용 (target_rules로 특정 배송 옵션 지정)
```

### 상품/그룹 범위는 `PromotionRule`로 지정

`target_type = "items"`일 때 `target_rules` 관계(pivot: `application_method_target_rules`)를 통해 `PromotionRule`을 연결한다.

파일: [`packages/modules/promotion/src/models/promotion-rule.ts`](../../packages/modules/promotion/src/models/promotion-rule.ts)

```
PromotionRule:
  attribute = "product_collection_id"   ← 적용 대상 속성
  operator  = "in"                      ← 포함 여부
  values    = [{ value: "pcol_brand_a" }]
```

사용 가능한 `attribute` 예시:

| attribute 값 | 의미 |
|-------------|------|
| `product_id` | 특정 상품 ID |
| `product_type_id` | 상품 유형 (예: 의류, 악세사리) |
| `product_collection_id` | 상품 컬렉션 (브랜드 그룹 등) |
| `product_tag_id` | 상품 태그 |
| `customer_group_id` | 고객 그룹 |

### `PromotionRule` 평가 로직

파일: [`packages/modules/promotion/src/utils/validations/promotion-rule.ts`](../../packages/modules/promotion/src/utils/validations/promotion-rule.ts)

`areRulesValidForContext(rules, context)` — **모든 룰 AND 조건**:

```typescript
return rules.every(rule => evaluateRuleValueCondition(rule, context))
```

`in` 연산자 동작: context 값 중 하나라도 rule values에 포함되면 통과.
`eq` 연산자 동작: context 값 전체가 rule values 안에 있어야 통과.

## 2. 할인액 분담 방식 (`allocation`)

파일: [`packages/modules/promotion/src/models/application-method.ts`](../../packages/modules/promotion/src/models/application-method.ts)  
계산: [`packages/core/utils/src/totals/promotion/index.ts`](../../packages/core/utils/src/totals/promotion/index.ts)

`target_type = "items"`일 때만 적용. 3가지 값:

### `allocation = "each"`

조건에 맞는 각 아이템에 독립적으로 동일 할인 적용.

```
아이템 A (25,000원) → 할인 3,000원
아이템 B (25,000원) → 할인 3,000원
총 할인: 6,000원
```

**과세 영향**: 아이템별 할인액이 동일하므로 과세 기준 금액 = (25,000 - 3,000) × 2 = 44,000원

### `allocation = "across"`

조건에 맞는 아이템 전체에 걸쳐 비례 배분.

계산 로직 (`packages/core/utils/src/totals/promotion/index.ts:118-146`):

```
할인액 10,000원을 아이템 A(소계 30,000원)와 B(소계 20,000원)에 분배

lineItemsAmount = 30,000 + 20,000 = 50,000

아이템 A의 할인액 = (30,000 / 50,000) × 10,000 = 6,000원
아이템 B의 할인액 = (20,000 / 50,000) × 10,000 = 4,000원
```

구현 (`getPromotionValueForFixed`, `totals/promotion/index.ts:19-35`):
```typescript
promotionValueForItem = (lineItemAmount / lineItemsAmount) * promotion.value
```

**과세 영향**: 아이템별 비례 배분 → 아이템A 과세 기준 = 24,000원, 아이템B = 16,000원. `each`와 결과가 다르므로 세금 신고액이 달라진다.

### `allocation = "once"`

조건에 맞는 아이템 중 첫 번째에만 한 번 적용.

## 3. 자동 적용 vs 코드 입력

파일: [`packages/modules/promotion/src/models/promotion.ts`](../../packages/modules/promotion/src/models/promotion.ts)

```
Promotion.is_automatic
  true  → Cart에 자동 적용 (기획전, 체험단 등 기간 조건 설정)
  false → Promotion.code를 Cart에 명시적으로 추가해야 적용 (쿠폰)
```

두 방식 모두 `PromotionRule`로 적용 조건을 동일하게 표현. 기간 조건은 `Campaign.starts_at / ends_at`으로 처리.

## 4. 적용 흐름 (장바구니 기준)

파일: [`packages/core/core-flows/src/cart/workflows/update-cart-promotions.ts`](../../packages/core/core-flows/src/cart/workflows/update-cart-promotions.ts)

```
POST /carts/:id/promotions
  → updateCartPromotionsWorkflow
    → getActionsToComputeFromPromotionsStep
        → PromotionModuleService.computeActions(cart, codes)
            1. buildPromotionRuleQueryFilterFromContext()
               └─ DB에서 자동 프로모션 사전 필터링 (SQL anti-join)
            2. areRulesValidForContext(promotion.rules, context)
               └─ ORDER 스코프 조건 평가 (AND)
            3. getComputedActionsForItems()
               └─ target_rules 평가 → 대상 아이템 필터링 → allocation 분배 계산
            4. getComputedActionsForShippingMethods()
               └─ target_rules 평가 → 배송 방법 필터링
    → prepareAdjustmentsFromPromotionActionsStep
    → createLineItemAdjustmentsStep (각 아이템에 Adjustment 행 INSERT)
    → createShippingMethodAdjustmentsStep (배송 방법에 Adjustment 행 INSERT)
```

## 5. 복수 프로모션의 순차 적용

여러 프로모션이 동시에 적용될 때, `across` 타입은 이전 프로모션이 적용된 잔여 금액 기준으로 재계산한다.

파일: [`packages/modules/promotion/src/utils/compute-actions/line-items.ts`](../../packages/modules/promotion/src/utils/compute-actions/line-items.ts)

```typescript
// 각 프로모션 적용 시 이미 적용된 금액을 차감
lineItemsAmount = applicableItems.reduce(
  (acc, item) => MathBN.sub(
    MathBN.add(acc, item.subtotal),
    appliedPromotionsMap.get(item.id) ?? 0  // 이전 프로모션 누적액 차감
  ),
  MathBN.convert(0)
)
```

## 6. 요구사항과의 Gap

| 요구사항 항목 | Medusa 지원 여부 | 비고 |
|-------------|----------------|------|
| 상품별 쿠폰 | ✅ `target_type=items` + `PromotionRule(attribute=product_id)` | |
| 상품 그룹별 쿠폰 | ✅ `PromotionRule(attribute=product_collection_id)` | `product_type_id`, `product_tag_id` 등도 가능 |
| 전체 주문 단위 쿠폰 | ✅ `target_type=order` | |
| 배송비 할인 | ✅ `target_type=shipping_methods` | |
| 할인액 비례 분담 | ✅ `allocation=across` | |
| 기간 한정 할인 | ✅ `Campaign.starts_at / ends_at` | |
| 브랜드 내 특정 상품 교집합 적용 | ✅ 복수 `PromotionRule` AND 조건 조합 | |
| 쿠폰 사용 횟수 제한 | ✅ `Promotion.limit / used` (2.12.0+) | |
| 고객별 사용 횟수 제한 | ✅ `CampaignBudget(type=use_by_attribute)` + `CampaignBudgetUsage` | |
| 포인트 사용 | ✅ `CreditLine` (별도 구조, 프로모션 아님) | 아래 정산-과세 문서 참조 |
