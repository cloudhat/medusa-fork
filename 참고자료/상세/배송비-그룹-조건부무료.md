# 배송비 그룹 구조 및 조건부 무료배송 — 요구사항과 Medusa 구현 대응 분석

요구사항:
- "상품군 단위: 배송그룹이 있고 거기에 상품이 묶여야 함"
- "일정 액수 이상 주문해야 조건부 배송비 무료가 적용 가능"

## 요약

Medusa의 배송 계층은 `FulfillmentSet → ServiceZone → GeoZone / ShippingOption → ShippingOptionRule` 구조다.
- **지역별 배송비**: ServiceZone + GeoZone 분리로 구현 가능
- **조건부 무료배송**: `ShippingOptionRule`의 attribute/operator/value 조합으로 구현
- **상품군 배송 그룹**: `ShippingProfile`로 상품에 배송 특성 부여
- **부분 반품 후 배송비 재청구**: Medusa에 자동화 로직 없음 — 커스텀 구현 필요

## 1. 배송 계층 구조

```
FulfillmentSet ("일반 배송")
 ├── ServiceZone ("일반 지역")
 │    ├── GeoZone (type=country, country_code="kr")
 │    └── ShippingOption ("CJ 대한통운 일반", amount=3000, price_type=flat)
 │         └── ShippingOptionRule (cart.subtotal >= 50000 → 무료배송 조건)
 └── ServiceZone ("제주/도서산간")
      ├── GeoZone (type=province, country_code="kr", province_code="jeju")
      └── ShippingOption ("CJ 대한통운 도서산간", amount=6000, price_type=flat)
```

## 2. 지역별 배송비 (도서산간)

### `GeoZone.type` 정밀도 계층

| type | 필요 필드 | 사용 시나리오 |
|------|---------|-------------|
| `country` | `country_code` | 한국 전체 |
| `province` | `country_code` + `province_code` | 제주도 전체 |
| `city` | `country_code` + `province_code` + `city` | 특정 시/군/구 |
| `zip` | `country_code` + `postal_expression` (JSON) | 우편번호 범위 |

## 3. 조건부 무료배송 (`ShippingOptionRule`)

파일: [`packages/modules/fulfillment/src/models/shipping-option-rule.ts`](../../packages/modules/fulfillment/src/models/shipping-option-rule.ts)

### 구현 방식

5만원 이상 무료배송:
```
ShippingOptionRule:
  attribute = "cart.subtotal"
  operator  = "gte"
  value     = 50000
```

이 룰은 Cart의 `subtotal`이 50,000 이상일 때만 해당 ShippingOption이 `listShippingOptionsForCart` 결과에 포함된다.

무료배송을 별도 `ShippingOption`으로 구현하는 방법 (amount=0):
```
ShippingOption ("무료배송", amount=0, price_type=flat)
  └── ShippingOptionRule (cart.subtotal >= 50000)

ShippingOption ("유료배송", amount=3000, price_type=flat)
  └── (룰 없음 → 항상 노출)
```

또는 `target_type=shipping_methods` 프로모션으로 배송비 할인(→3,000원 차감)을 구현하는 방법도 있다.

### 룰 평가 로직

파일: [`packages/modules/fulfillment/src/utils/utils.ts`](../../packages/modules/fulfillment/src/utils/utils.ts) — `isContextValid()` (line 69)

```typescript
const loopComparator = someAreValid ? rules.some : rules.every
return loopComparator.apply(rules, [predicate])
```

`listShippingOptionsForContext`는 `options` 없이 호출하므로 기본값 `{ someAreValid: false }` 적용 → **모든 룰 AND 조건**이다.

연산자:
- `in`: context 값이 rule values 배열 안에 있으면 통과
- `nin`: context 값이 rule values 배열 밖에 있으면 통과
- `gte`/`lte`/`gt`/`lt`: 숫자 또는 날짜 비교

## 4. 상품군 배송 그룹 (`ShippingProfile`)

파일: [`packages/modules/fulfillment/src/models/shipping-profile.ts`](../../packages/modules/fulfillment/src/models/shipping-profile.ts)

상품에 `ShippingProfile`을 연결해 배송 특성을 구분한다.

```
ShippingProfile (type="default")     → 일반 상품 배송 옵션 사용
ShippingProfile (type="cold_chain")  → 냉장 배송 전용 옵션만 사용
ShippingProfile (type="digital")     → 배송 불필요
```

`ShippingOption`이 `ShippingProfile`을 가리키므로(`belongsTo ShippingProfile`), 특정 Profile에 속한 상품이 장바구니에 있을 때 해당 Profile의 ShippingOption이 선택 대상이 된다.

**주의**: 이 매핑 강제(같은 장바구니에서 Profile별로 배송 방법을 분리 선택)는 Medusa 코어가 자동으로 처리하지 않는다. 프론트엔드에서 Profile 기준으로 배송 옵션을 분리 제시하는 UI 로직이 별도로 필요하다.

### Medusa가 자동 처리하지 않는 것 (사실)

코드베이스에서 다음 시나리오의 자동 처리 로직을 확인하지 못했다:
- 부분 반품으로 `cart.subtotal`이 무료배송 임계값 아래로 내려갈 때 **아웃바운드 배송비** 재청구
- `is_automatic=true` 프로모션으로 적용된 배송비 할인 취소

### 커스텀 구현 방향 (추정)

`order.return_requested` 이벤트를 구독해서:

1. 반품 후 주문 잔여 금액 계산
2. 무료배송 임계값과 비교
3. 임계값 이하이면 `PROMOTION_REMOVE` 또는 배송비 추가 `OrderChangeAction` 생성

```
// 이벤트 구독 예시 구조 (커스텀)
on("order.return_requested", async ({ order_id }) => {
  const order = await previewOrderChange(order_id)
  if (order.subtotal < FREE_SHIPPING_THRESHOLD) {
    // 배송비 추가 청구 OrderChangeAction 생성
  }
})
```

이 로직은 Medusa 코어에 없으며 직접 구현해야 한다.
