# 부분 반품/환불 처리 흐름 — 요구사항과 Medusa 구현 대응 분석

요구사항:
- "적용된 단위에 따라 증가 요소, 차감 요소가 변경돼야 함"
- "부분 주문취소/환불"

상위: [README.md](../개요/README.md)

---

## 요약

Medusa의 부분 반품은 4단계 워크플로우로 처리된다. 금액 변화는 `OrderChangeAction`에 쌓이고, `OrderSummary.pending_difference`로 표면화된다. 실제 환불 입금은 `refundPaymentsWorkflow`가 별도로 처리한다.

---

## 1. 4단계 워크플로우

```
1. beginReturnOrderWorkflow     → Return + OrderChange 생성
2. requestItemReturnWorkflow    → OrderChangeAction(RETURN_ITEM) 추가
3. confirmReturnRequestWorkflow → 확정 + ReturnItem 생성 + 버전 증가
4. confirmReturnReceiveWorkflow → 수령 확인 + 재고 반환
   (+ refundPaymentsWorkflow   → 실제 환불 트랜잭션 기록)
```

---

## 2. 단계별 상세

### 1단계: 반품 시작

파일: [`packages/core/core-flows/src/order/workflows/return/begin-return.ts`](../../packages/core/core-flows/src/order/workflows/return/begin-return.ts)

```
Return 생성 (status: OPEN)
OrderChange 생성 (change_type: "return_request", version: order.version + 1)
```

이 시점에서 어떤 품목도 지정되지 않음. `OrderChange.status = PENDING`.

### 2단계: 반품 품목 추가 (부분 수량 지정 가능)

파일: [`packages/core/core-flows/src/order/workflows/return/request-item-return.ts`](../../packages/core/core-flows/src/order/workflows/return/request-item-return.ts)

`requestItemReturnValidationStep`에서:
- 주문 취소 여부 확인
- 품목 존재 여부 확인
- 이미 반품 요청된 수량 초과 여부 확인

`OrderChangeAction` INSERT:
```typescript
{
  action: ChangeActionType.RETURN_ITEM,   // "RETURN_ITEM"
  details: {
    reference_id: item.id,               // OrderItem ID
    reason_id: item.reason_id,
    quantity: item.quantity,             // 부분 수량 지정 가능
    metadata: item.metadata,
  },
  // amount는 action 처리 시 unit_price × quantity로 계산됨
}
```

`OrderChangeAction.amount` 계산 시점:
파일: [`packages/modules/order/src/utils/actions/return-item.ts`](../../packages/modules/order/src/utils/actions/return-item.ts)

```typescript
return MathBN.mult(existing.unit_price, action.details.quantity)
// 세전 단가 × 반품 수량
```

이 amount가 `isDeduction: true`에 의해 `current_order_total`에서 차감된다.

### 3단계: 반품 요청 확정

파일: [`packages/core/core-flows/src/order/workflows/return/confirm-return-request.ts`](../../packages/core/core-flows/src/order/workflows/return/confirm-return-request.ts)

```
previewOrderChangeStep(order.id)      → 현재 상태 미리보기 (DB 저장 없음)
createReturnItemsFromActionsStep      → RETURN_ITEM 액션 → ReturnItem 레코드 변환
updateReturnsStep                     → Return.status = REQUESTED, requested_at = now()
confirmOrderChanges                   → OrderChange.status = CONFIRMED
  └─ applyOrderChanges_()            → 액션 일괄 반영, Order.version 증가
emitEventStep("order.return_requested")
createOrUpdateOrderPaymentCollectionWorkflow  → 결제 컬렉션 업데이트
```

확정 후:
- `OrderItem.return_requested_quantity` 증가
- `OrderSummary.pending_difference` 음수 (환불 필요 금액)
- 새 버전의 `OrderSummary` 행 INSERT

### 4단계: 수령 확인 및 환불

파일: [`packages/core/core-flows/src/order/workflows/return/confirm-receive-return-request.ts`](../../packages/core/core-flows/src/order/workflows/return/confirm-receive-return-request.ts)

전체 수령 여부 판정:
```typescript
const hasReceivedAllItems = retItems.every((item) => {
  const received = itemUpdates[item.item_id]?.received_quantity ?? item.received_quantity
  return MathBN.eq(received, item.quantity)
})
// 전체 수령 → Return.status = RECEIVED
// 부분 수령 → Return.status = PARTIALLY_RECEIVED
```

`adjustInventoryLevelsStep` → 재고 레벨 복원

실제 환불 트랜잭션은 별도 `refundPaymentsWorkflow`에서:

파일: [`packages/core/core-flows/src/payment/workflows/refund-payments.ts`](../../packages/core/core-flows/src/payment/workflows/refund-payments.ts)

```typescript
// 환불 트랜잭션은 음수 amount로 기록
addOrderTransactionStep({
  order_id: order.id,
  amount: MathBN.mult(paymentInput.amount, -1),  // 음수
  reference: "refund",
})
```

## 3. `OrderChangeAction` 종류별 금액 영향

파일: [`packages/modules/order/src/utils/actions/`](../../packages/modules/order/src/utils/actions/)

| Action | isDeduction | current_order_total | OrderItem 필드 변화 |
|--------|-------------|---------------------|-------------------|
| `RETURN_ITEM` | true | 감소 | `return_requested_quantity` 증가 |
| `RECEIVE_RETURN_ITEM` | true | 감소 | `return_received_quantity` 증가, `return_requested_quantity` 감소 |
| `RECEIVE_DAMAGED_RETURN_ITEM` | true | 감소 | `return_dismissed_quantity` / `written_off_quantity` 증가 |
| `ITEM_REMOVE` | true | 감소 | 품목 수량 감소 |
| `SHIPPING_ADD` | false | 증가 | 배송 방법 추가 |
| `PROMOTION_REMOVE` | false | 증가 | 할인 취소 (금액 복원) |

## 4. `pending_difference`로 환불 금액 추적

파일: [`packages/modules/order/src/utils/calculate-order-change.ts`](../../packages/modules/order/src/utils/calculate-order-change.ts)

```
pending_difference = current_order_total - transaction_total

예시:
  original_order_total = 100,000원
  반품 아이템 unit_price × quantity = 30,000원
  current_order_total = 100,000 - 30,000 = 70,000원
  transaction_total (이미 결제된 금액) = 100,000원
  pending_difference = 70,000 - 100,000 = -30,000원  ← 환불해야 할 금액
```

`decorateCartTotals()` 내 계산 ([`packages/core/utils/src/totals/cart/index.ts`](../../packages/core/utils/src/totals/cart/index.ts)):

```
pending_difference = total - sum(items.return_requested_total) - transaction_total
```

## 5. 라인 아이템 합계에서 반품 수량 차감

파일: [`packages/core/utils/src/totals/line-item/index.ts`](../../packages/core/utils/src/totals/line-item/index.ts)

`getLineItemTotals()`에서 현재 유효 수량 계산:

```typescript
const currentQuantity = MathBN.sub(
  item.quantity,
  MathBN.add(item.detail.return_received_quantity, item.detail.return_dismissed_quantity)
)
// 반품 수령 + 반품 기각 수량 차감 후 잔여 수량으로 subtotal 계산
```

반품 요청(`return_requested_quantity`)은 `currentQuantity`에서 차감되지 않고, `refundable_total` 계산에만 영향을 미친다. 즉 아직 수령 확인이 안 된 품목은 여전히 `subtotal`에 포함된 상태다.

## 6. 요구사항과의 Gap

| 요구사항 항목 | Medusa 지원 여부 | 비고 |
|-------------|----------------|------|
| 부분 수량 반품 | ✅ `OrderChangeAction.details.quantity`로 수량 지정 | |
| 환불 금액 추적 | ✅ `pending_difference`, `refunded_total` | |
| 부분 수령 | ✅ `Return.status = PARTIALLY_RECEIVED` | |
| 반품 사유 | ✅ `ReturnReason` + `ReturnItem.reason_id` | |
| 배송비 재청구 (조건부 무료배송 이탈) | ❌ 자동 처리 없음 | 커스텀 이벤트 구독 필요 (배송비-그룹-조건부무료.md 참조) |
| 할인 취소 (쿠폰 조건 이탈) | 부분적 — `PROMOTION_REMOVE` 액션 존재하나 반품 워크플로우에서 자동 미연동 | |
| 세금 재계산 | ✅ `decorateCartTotals()`가 매 조회 시 재계산 | DB에 세금 합계 직접 저장 안 함 |
